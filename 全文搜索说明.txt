一、最终方案（一句话）
----------------------
和标题搜索完全同一套路子：**构建时生成一个静态 JSON 索引 → 前端拉一次 → 本地匹配**。
区别只是这个索引里多带了「正文纯文本」，所以搜「ORCSOFT」这种词，
正文里出现过的文章就会列出来（不是只匹配标题）。

  /api/postTitles.json      标题索引，体积很小，导航栏随页面预加载（原有）
  /api/postSearchIndex.json 正文索引，构建时生成，搜索页第一次搜索时拉一次

两个索引共用同一份匹配代码（src/utils/site-search.ts）：
先精确子串（indexOf），失配再按相似度容错。

没有分片、没有并发请求、没有进度条，也不需要 Pagefind。

二、实测（全部 1276 篇真实文章）
--------------------------------
· 索引单文件 2.20 MB，gzip 后约 972 KB，只下载一次，之后走内存缓存
· 搜「ORCSOFT」→ 命中正文含「社团名：#ORCSOFT」的文章《你妈真漂亮/你妈真是个好女人》，相似度 100%
· 搜「orcsoft」（小写）→ 同样命中（大小写 / 全半角不敏感）
· 搜「orcsof」（少字母但仍是子串）→ 命中，100%
· 搜「ORCSFT」（少一个字母的错别字，非子串）→ 80% 阈值下命中，相似度 86%；拉到 100% 就不命中
· 多关键词用空格 / 标点分隔，AND 关系，词序不限（例：「ORCSOFT 社团」）
· 首次搜索（含下载 + 解析 + 扫描 93 万字）约 140 ms（本机 localhost）；
  索引在内存后，后续每次按键 1~30 ms

四、可调参数（src/config/searchConfig.ts）
------------------------------------------
  minSimilarity / maxSimilarity / defaultSimilarity  滑杆范围与默认值（80 ~ 100，默认 80）
  quickSearchSimilarity   导航栏快速搜索的相似度（默认 80）
  quickSearchLimit        导航栏最多显示几条（默认 5）
  pageResultLimit         搜索页最多显示几条（默认 300）
  maxCharsPerPost         单篇文章最多收录多少字（默认 20000，防超长文章把索引撑大）

五、部署（GitHub Pages / Cloudflare 静态托管都行）
--------------------------------------------------
你的 wrangler.jsonc 里只有 `assets: { directory: "./dist" }`、没有 main，
属于纯静态资源部署；构建产物里会多出一个
  dist/api/postSearchIndex.json
它就是一个普通静态文件（2 MB 左右，远低于 Cloudflare 25 MiB 单文件上限），
CDN 会正常 gzip/brotli 压缩，请求数也只多 1 个。

所以：
  · GitHub Pages（.github/workflows/deploy.yml 用的 pnpm build → dist）→ 直接可用
  · Cloudflare 静态资源（wrangler deploy / Pages 连接仓库，命令 pnpm build）→ 直接可用
  · 不要设 CF_WORKERS 环境变量：设了会切到 @astrojs/cloudflare 适配器，
    输出结构变成 dist/client + dist/server，和你现在的 wrangler.jsonc 不匹配。
  · 如果用了「缓存一切」的自定义 CDN 规则，建议给 /api/*.json 保留较短缓存，
    否则发新文章后索引可能最多滞后一个缓存周期。

构建：cd /sdcard/NP/mcp/Firefly && pnpm install && pnpm build
